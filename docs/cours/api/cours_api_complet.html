2 Module 1 : Fondamentaux des APIs

2.1 1.1 Qu’est-ce qu’une API ?

2.1.1 Définition

Une API (Application Programming Interface) est un contrat qui définit comment des logiciels communiquent entre eux. C’est une interface qui expose des fonctionnalités d’un système à d’autres systèmes.

Analogie : Imaginez un restaurant. Le menu (API) liste les plats disponibles (endpoints). Le serveur (protocole HTTP) transmet votre commande (requête) à la cuisine (serveur) et vous rapporte le plat (réponse).

Définition technique

Une API est définie par un contrat qui précise :
- Les endpoints disponibles (ex : /users, /orders/{id}, /buy/browse/v1/item_summary/search)
- Les méthodes HTTP autorisées (ex : GET, POST, PUT, DELETE)
- Le format d’échange des données (ex : JSON, XML, Protocol Buffers)
- Les règles de sécurité (ex : OAuth2, API Key, Authorization: Bearer )
- Le schéma des requêtes et réponses (ex : { “email”: “string”, “password”: “string” })
- Les codes de retour (ex : 200, 201, 400, 401, 404, 500)
- Le versioning (ex : /api/v1/users, /api/v2/users)

On peut voir une API comme une couche d’abstraction qui expose des fonctionnalités d’un système via une interface stable et documentée.

2.1.1.1 Focus sur le contrat

Le contrat d’API — Définition globale

Le contrat d’API est la description formelle et stable de tout ce qu’un client doit savoir pour interagir correctement avec une API.
Il définit ce qui est observable et garanti entre le client et le serveur.

2.1.1.1.2 Endpoints

Les points d’entrée accessibles via une URL.

Exemple :

GET /users  
POST /orders  
DELETE /users/{id}

Ils définissent où appeler l’API.

2.1.1.1.3 Méthodes HTTP

Les actions autorisées sur chaque endpoint :

- GET → Lire
- POST → Créer
- PUT / PATCH → Modifier
- DELETE → Supprimer
- PATCH -> Modification partielle 
- HEAD -> Metadatas liées à la requête

Elles définissent quelle opération est permise.

2.1.1.1.4 Format d’échange

Le format des données envoyées et reçues :

  • JSON
  • XML
  • Protocol Buffers

Il définit comment les données sont structurées.

2.1.1.1.5 Schéma des données

La structure précise des objets :

  • Nom des champs
  • Types (string, number, boolean…)
  • Champs obligatoires ou optionnels
  • Contraintes (format email, min/max…)

Il définit quoi envoyer et quoi recevoir exactement.

2.1.1.1.6 Paramètres

Les paramètres acceptés :

  • Path parameters (/users/{id})
  • Query parameters (?limit=10)
  • Body (JSON)

Ils définissent comment personnaliser une requête.

2.1.1.1.7 Authentification & Sécurité

Les règles pour accéder à l’API :

  • Bearer Token
  • API Key
  • OAuth2

Elles définissent comment prouver son identité.

2.1.1.1.8 Codes de retour HTTP

Les statuts renvoyés selon le résultat :

  • 200 → Succès
  • 201 → Créé
  • 400 → Requête invalide
  • 401 → Non authentifié
  • 404 → Ressource introuvable
  • 500 → Erreur serveur

Ils définissent comment interpréter la réponse.

2.1.1.1.9 Structure des erreurs

Exemple :

{
  "error": {
    "code": "INVALID_EMAIL",
    "message": "Email format is invalid"
  }
}

Elle définit comment comprendre les échecs.

2.1.1.1.10 Versioning

Permet de faire évoluer l’API sans casser les clients :

/api/v1/users
/api/v2/users

Il garantit la stabilité dans le temps.

2.1.2 Vue architecturelle

Dans une architecture distribuée moderne :

Client → API → Service → Base de données

L’API joue le rôle de façade :
- Elle valide les entrées
- Elle orchestre la logique métier
- Elle formate la réponse
- Elle gère la sécurité

2.2 1.2 REST vs Autres Architectures

2.2.1 Architecture REST (Representational State Transfer)

REST est un style d’architecture pour les systèmes distribués, basé sur 6 principes :

  1. Client-Serveur : Séparation des préoccupations
  2. Sans état (Stateless) : Chaque requête contient toutes les informations nécessaires
  3. Cacheable : Les réponses doivent indiquer si elles peuvent être mises en cache
  4. Interface uniforme : URLs standard, méthodes HTTP
  5. Système en couches : Architecture modulaire
  6. Code à la demande (optionnel) : Le serveur peut envoyer du code exécutable

Précisons ces points !
Stateless (REST)
Le serveur ne conserve aucun état de session entre deux requêtes.
Chaque requête doit contenir : - l’identification (ex: JWT)
- le contexte nécessaire
- toutes les données utiles

Stateful (l’inverse)
Le serveur stocke un état en mémoire ou en base.
Exemple classique :
- Login
- Serveur crée une session

Cacheable (REST)
Dans REST, cacheable signifie que les réponses HTTP doivent indiquer clairement si elles peuvent être stockées temporairement afin de :
- Réduire la charge serveur
- Diminuer la latence
- Économiser la bande passante
- Améliorer la scalabilité

On ne met pas en cache “une API”, mais la réponse HTTP complète :
- Status code
- Headers
- Body (ex: JSON)

Quelles requêtes sont concernées ?
Principalement :

- `GET`    
- `HEAD`

Pas concernées :

- `POST`    
- `PUT`    
- `PATCH`    
- `DELETE`

(car elles modifient l’état)

Deux mécanismes principaux
Cache par durée

Cache-Control: max-age=3600

→ La réponse est valide pendant 1 heure. Le client ne recontacte pas le serveur durant ce délai.

Cache conditionnel (ETag)

ETag: v1

Lors d’une nouvelle requête : If-None-Match: v1 Si la ressource n’a pas changé : 304 Not Modified
→ Pas de renvoi du JSON.

ETag = identifiant de version de la ressource.

Où le cache est-il stocké ?
Navigateur
Proxy
API Gateway
CDN (Content Delivery Network) Réseau de serveurs stockant des copies de ressources.

Directives importantes

Cache-Control: public   # Cache possible par CDN
Cache-Control: private  # Cache navigateur uniquement
Cache-Control: no-store # Aucun stockage

Pourquoi c’est crucial ?
Dans un système distribué :
Le réseau est lent
Les serveurs coûtent cher
La latence est critique
Un bon cache peut diviser la charge backend par 10 ou plus.

Interface uniforme
L’interface uniforme est le principe REST selon lequel toutes les ressources sont manipulées de la même manière, en utilisant des règles standardisées.
Concrètement :
Les ressources sont identifiées par des URI (/users/42)
Les actions sont exprimées via les méthodes HTTP (GET, POST, PUT, DELETE, PATCH)
Les échanges utilisent des représentations standard (souvent JSON)
Les messages sont auto-descriptifs (headers HTTP explicites)

Layered System (système en couches)
Dans une API REST, une architecture en couches signifie que :
Le système est composé de plusieurs niveaux intermédiaires, le client ne sait pas avec quelle couche il communique réellement.
Chaque couche a une responsabilité spécifique.

Concrètement, cela veut dire quoi ?
Une requête peut traverser plusieurs composants :
Client
→ Cache
→ Proxy
→ API Gateway
→ Service d’authentification
→ Service métier
→ Base de données

Le client ne voit qu’un seul point d’entrée : https://api.example.com
Il ignore totalement :
s’il y a un cache
s’il y a plusieurs microservices

Cette séparation permet :
Scalabilité
On peut ajouter ou modifier une couche sans impacter le client.

Sécurité
On peut insérer :
un firewall
une couche d’authentification
un système de rate limiting

Maintenabilité
Chaque couche a une responsabilité unique :
Auth
Logging
Cache
Business logic

L’inverse (non modulaire)
Client → Serveur unique → Base
Pas d’intermédiaire, tout est centralisé dans un seul composant.

2.2.2 Comparaison avec d’autres architectures

Architecture Protocole Format Cas d’usage
REST HTTP/HTTPS JSON, XML APIs web modernes
SOAP HTTP, SMTP XML uniquement Systèmes legacy, transactions complexes
GraphQL HTTP JSON Requêtes flexibles, mobile
gRPC HTTP/2 Protocol Buffers Microservices, performance critique

eBay utilise REST pour ses APIs modernes (Buy, Sell, Commerce) et SOAP pour ses APIs traditionnelles (Trading, Shopping).

2.3 1.3 HTTP et ses Méthodes

2.3.1 Le protocole HTTP

HTTP (HyperText Transfer Protocol) est le protocole de communication du web. Une transaction HTTP se compose de :

CLIENT                           SERVEUR
  │                                 │
  ├──── Requête HTTP ──────────────>│
  │     (Méthode, URL, Headers)     │
  │                                 │
  │<──── Réponse HTTP ──────────────┤
        (Status, Headers, Body)     │

2.3.2 Les méthodes HTTP principales

Méthode Usage Idempotent Safe eBay Example
GET Récupérer une ressource ✅ ✅ Obtenir les détails d’un produit
POST Créer une ressource ❌ ❌ Créer un listing
PUT Remplacer une ressource ✅ ❌ Mettre à jour entièrement un listing
PATCH Modifier partiellement ❌ ❌ Modifier le prix d’un listing
DELETE Supprimer une ressource ✅ ❌ Supprimer un listing

Idempotent : Une opération peut être répétée sans effets de bord supplémentaires.
Safe : L’opération ne modifie pas l’état du serveur.

2.3.3 Exemple concret avec l’API eBay Browse

# GET : Rechercher des produits sur eBay
# Endpoint : /buy/browse/v1/item_summary/search
GET https://api.ebay.com/buy/browse/v1/item_summary/search?q=iphone&limit=5

# POST : Créer un listing (Sell API)
# Endpoint : /sell/inventory/v1/offer
POST https://api.ebay.com/sell/inventory/v1/offer
Body: { "sku": "ABC123", "marketplaceId": "EBAY_US", ... }

# PUT : Mettre à jour un listing complètement
PUT https://api.ebay.com/sell/inventory/v1/offer/12345
Body: { "sku": "ABC123", "quantity": 10, ... }

# DELETE : Retirer un listing
DELETE https://api.ebay.com/sell/inventory/v1/offer/12345

2.4 1.4 Structure des Requêtes et Réponses

2.4.1 Anatomie d’une requête HTTP

POST /sell/inventory/v1/offer HTTP/1.1
Host: api.ebay.com
Authorization: Bearer v^1.1#i^1#...
Content-Type: application/json
X-EBAY-C-MARKETPLACE-ID: EBAY_US

{
  "sku": "LAPTOP-001",
  "marketplaceId": "EBAY_US",
  "format": "FIXED_PRICE",
  "availableQuantity": 5,
  "pricingSummary": {
    "price": {
      "value": "999.99",
      "currency": "USD"
    }
  }
}

Composants :
1. Ligne de requête : Méthode + URL + Version HTTP
2. Headers : Métadonnées (autorisation, type de contenu)
3. Body : Données (pour POST/PUT/PATCH)

2.4.2 Anatomie d’une réponse HTTP

HTTP/1.1 201 Created
Content-Type: application/json
Date: Mon, 09 Feb 2026 10:30:00 GMT

{
  "offerId": "1234567890",
  "status": "PUBLISHED",
  "listingPolicies": {
    "fulfillmentPolicyId": "6789012345",
    "paymentPolicyId": "3456789012"
  }
}

Composants :
1. Ligne de statut : Version HTTP + Code de statut + Message
2. Headers : Métadonnées de réponse
3. Body : Données retournées (généralement JSON)

2.4.3 Codes de statut HTTP

Code Signification Exemple eBay
2xx Succès
200 OK Requête réussie
201 Created Listing créé
204 No Content Suppression réussie
3xx Redirection
301 Moved Permanently URL changée définitivement

2.5 1.5 Formats de Données : JSON vs XML

2.5.1 JSON (JavaScript Object Notation)

Format léger et lisible par l’homme, standard pour les APIs REST modernes.

{
  "itemId": "v1|110547012345|0",
  "title": "Apple iPhone 14 Pro Max - 256GB",
  "price": {
    "value": "1099.00",
    "currency": "USD"
  },
  "condition": "NEW",
  "seller": {
    "username": "apple_store",
    "feedbackScore": 98765
  },
  "itemLocation": {
    "city": "Cupertino",
    "country": "US"
  }
}

Avantages :
- ✅ Léger et rapide à parser
- ✅ Lisible par l’homme
- ✅ Support natif en JavaScript
- ✅ Utilisé par toutes les APIs eBay modernes (REST)

2.5.2 XML (eXtensible Markup Language)

Format verbeux mais strictement typé, utilisé par les APIs SOAP.

<?xml version="1.0" encoding="utf-8"?>
<GetItemResponse xmlns="urn:ebay:apis:eBLBaseComponents">
  <Timestamp>2026-02-09T10:30:00.000Z</Timestamp>
  <Ack>Success</Ack>
  <Item>
    <ItemID>110547012345</ItemID>
    <Title>Apple iPhone 14 Pro Max - 256GB</Title>
    <SellingStatus>
      <CurrentPrice currencyID="USD">1099.00</CurrentPrice>
    </SellingStatus>
    <Seller>
      <UserID>apple_store</UserID>
      <FeedbackScore>98765</FeedbackScore>
    </Seller>
  </Item>
</GetItemResponse>

Avantages :
- Validation stricte avec schémas (XSD)
- Support des namespaces
- Utilisé par les APIs eBay traditionnelles (Trading, Shopping)

Documentation eBay : Les APIs REST eBay utilisent exclusivement JSON. Les APIs traditionnelles (SOAP) utilisent XML.

3 Module 2 : Authentification et Sécurité

3.1 2.1 Pourquoi l’Authentification ?

L’authentification garantit :

  1. Identification : Qui fait la requête ?
  2. Autorisation : A-t-il le droit de le faire ?
  3. Traçabilité : Audit et logs
  4. Limitation : Rate limiting par utilisateur
  5. Facturation : Suivi de la consommation

eBay utilise OAuth 2.0 pour toutes ses APIs modernes.

3.2 2.2 Les Application Keysets eBay

Avant de faire des appels API, vous devez créer un keyset (jeu de clés) sur le portail développeur eBay.

Environnement Usage URL API Données

3.3 2.3 OAuth 2.0 : Le Standard d’Authentification

3.3.1 Qu’est-ce qu’OAuth 2.0 ?

OAuth 2.0 est un protocole d’autorisation qui permet à une application d’accéder aux ressources d’un utilisateur sans connaître son mot de passe.

3.3.2 Deux types de tokens OAuth eBay

3.3.2.1 1. Application Access Token (App Token)

  • Usage : Accès aux données publiques (recherche, browse)
  • Durée : 2 heures
  • Pas de consentement utilisateur requis

       │

│   Search)   │
└─────────────┘

3.3.2.2 2. User Access Token (User Token)

  • Usage : Accès aux données privées de l’utilisateur (listings, ordres)
  • Durée : Varie selon les scopes
  • Consentement utilisateur obligatoire

def get_application_token(client_id, client_secret, environment='sandbox'):
    """
    Obtient un Application Access Token via le flux Client Credentials.
    
    Ce token permet d'accéder aux APIs publiques (Browse, Search) sans
    nécessiter de consentement utilisateur.
    
    Args:
        client_id (str): L'App ID de votre keyset eBay
        client_secret (str): Le Cert ID de votre keyset eBay
        environment (str): 'sandbox' ou 'production'
    
    Returns:
        dict: Contient 'access_token', 'token_type', 'expires_in', 'expires_at'
    
    Raises:
        requests.exceptions.RequestException: En cas d'erreur HTTP
    """
    
    # 1. Encoder les credentials en Base64
    # Format : "Client_ID:Client_Secret" encodé en base64
    credentials = f"{client_id}:{client_secret}"
    encoded_credentials = base64.b64encode(credentials.encode()).decode()
    
    # 2. Construire les headers HTTP
    headers = {
        'Content-Type': 'application/x-www-form-urlencoded',
        'Authorization': f'Basic {encoded_credentials}'
    }
    
    # 3. Corps de la requête : grant_type et scopes
    data = {
        'grant_type': 'client_credentials',
        'scope': 'https://api.ebay.com/oauth/api_scope'
    }
    
    # 4. URL du endpoint OAuth selon l'environnement
    token_url = API_URLS[environment]['oauth']
    
    print(f"Demande de token à : {token_url}")
    
    # 5. Envoyer la requête POST
    try:
        response = requests.post(
            token_url,
            headers=headers,
            data=data,
            timeout=10  # Timeout de 10 secondes
        )
        
        # 6. Vérifier le code de statut HTTP
        response.raise_for_status()  # Lève une exception si status >= 400
        
        # 7. Parser la réponse JSON
        token_data = response.json()
        
        # 8. Calculer la date d'expiration
        expires_in = token_data.get('expires_in', 7200)  # Par défaut 2h
        expires_at = datetime.now() + timedelta(seconds=expires_in)
        
        # 9. Ajouter les métadonnées
        token_data['expires_at'] = expires_at.isoformat()
        token_data['environment'] = environment
        
        print(f"Token obtenu avec succès !")
        print(f"   Type : {token_data.get('token_type')}")
        print(f"   Expire dans : {expires_in} secondes ({expires_in//3600}h)")
        print(f"   Expiration : {expires_at.strftime('%Y-%m-%d %H:%M:%S')}")
        
        return token_data
        
    except requests.exceptions.HTTPError as e:
        print(f"Erreur HTTP {e.response.status_code} : {e.response.text}")
        raise
    except requests.exceptions.RequestException as e:
        print(f"Erreur de requête : {str(e)}")
        raise

import urllib.parse
import secrets

def generate_authorization_url(client_id, redirect_uri, scopes, environment='sandbox'):
    """
    Génère l'URL de consentement eBay pour le flux Authorization Code.
    
    L'utilisateur doit être redirigé vers cette URL pour approuver les scopes.
    
    Args:
        client_id (str): L'App ID de votre keyset
        redirect_uri (str): URL de redirection après consentement (doit être configurée dans votre app)
        scopes (list): Liste des scopes demandés
        environment (str): 'sandbox' ou 'production'
    
    Returns:
        tuple: (authorization_url, state)
    """
    
    # Base URL selon l'environnement
    auth_base_urls = {
        'sandbox': 'https://auth.sandbox.ebay.com/oauth2/authorize',
        'production': 'https://auth.ebay.com/oauth2/authorize'
    }
    
    # Générer un état aléatoire pour prévenir les attaques CSRF
    state = secrets.token_urlsafe(32)
    
    # Construire les paramètres de la requête
    params = {
        'client_id': client_id,
        'redirect_uri': redirect_uri,
        'response_type': 'code',
        'scope': ' '.join(scopes),
        'state': state
    }
    
    # Encoder l'URL
    authorization_url = f"{auth_base_urls[environment]}?{urllib.parse.urlencode(params)}"
    
    print(f"🔗 URL de consentement générée :")
    print(f"   {authorization_url}")
    print(f"\n State (à vérifier lors du callback) : {state}")
    
    return authorization_url, state


def exchange_code_for_token(client_id, client_secret, code, redirect_uri, environment='sandbox'):
    """
    Échange le code d'autorisation contre un User Access Token.
    
    Cette fonction est appelée après que l'utilisateur a approuvé les scopes
    et a été redirigé vers votre redirect_uri avec un code d'autorisation.
    
    Args:
        client_id (str): L'App ID
        client_secret (str): Le Cert ID
        code (str): Le code d'autorisation reçu dans l'URL de callback
        redirect_uri (str): Le même redirect_uri utilisé lors de l'autorisation
        environment (str): 'sandbox' ou 'production'
    
    Returns:
        dict: Contient 'access_token', 'refresh_token', 'expires_in', etc.
    """
    
    # Encoder les credentials
    credentials = f"{client_id}:{client_secret}"
    encoded_credentials = base64.b64encode(credentials.encode()).decode()
    
    headers = {
        'Content-Type': 'application/x-www-form-urlencoded',
        'Authorization': f'Basic {encoded_credentials}'
    }

        'grant_type': 'authorization_code',
        'code': code,
        'redirect_uri': redirect_uri
    }
    
    token_url = API_URLS[environment]['oauth']
    
    print(f" Échange du code d'autorisation contre un token...")
    
    try:

        return token_data
        
    except requests.exceptions.HTTPError as e:

def build_ebay_headers(access_token, marketplace_id='EBAY_US', content_type='application/json'):
    """
    Construit les headers HTTP requis pour les appels eBay API.
    
    Args:
        access_token (str): Le token OAuth (app ou user)
        marketplace_id (str): ID du marketplace (EBAY_US, EBAY_FR, etc.)
        content_type (str): Type de contenu (application/json par défaut)
    
    Returns:
        dict: Headers HTTP prêts à l'emploi
    """
    
    headers = {
        # 1. Authentification OAuth 2.0
        'Authorization': f'Bearer {access_token}',
        
        # 2. Type de contenu (pour POST/PUT/PATCH)
        'Content-Type': content_type,
        
        # 3. Marketplace cible (requis pour la plupart des APIs)
        'X-EBAY-C-MARKETPLACE-ID': marketplace_id,
        
        # 4. Accept (format de réponse souhaité)
        'Accept': 'application/json',
        
        # 5. User-Agent (bonne pratique)
        'User-Agent': 'MonApp/1.0 (Formation API)'
    }
    
    return headers

class EbayAPIError(Exception):

def make_ebay_request(method, endpoint, access_token, 
                      marketplace='EBAY_US', environment='sandbox',
                      params=None, json_data=None, max_retries=3):
    """
    Fonction générique pour faire des appels à l'API eBay avec gestion d'erreurs.
    
    Args:
        method (str): Méthode HTTP (GET, POST, PUT, DELETE)
        endpoint (str): Endpoint API (ex: '/buy/browse/v1/item_summary/search')
        access_token (str): Token OAuth
        marketplace (str): Marketplace ID
        environment (str): 'sandbox' ou 'production'
        params (dict): Paramètres de requête (pour GET)
        json_data (dict): Corps de la requête (pour POST/PUT)
        max_retries (int): Nombre maximum de tentatives en cas d'erreur 5xx
    
    Returns:
        dict: Réponse JSON de l'API
    
    Raises:
        EbayAPIError: En cas d'erreur API
    """
    
    base_url = API_URLS[environment]['api']
    url = f"{base_url}{endpoint}"
    headers = build_ebay_headers(access_token, marketplace)
    
    for attempt in range(max_retries):
        try:
            # Faire la requête selon la méthode
            if method.upper() == 'GET':
                response = requests.get(url, headers=headers, params=params, timeout=15)
            elif method.upper() == 'POST':
                response = requests.post(url, headers=headers, json=json_data, timeout=15)
            elif method.upper() == 'PUT':
                response = requests.put(url, headers=headers, json=json_data, timeout=15)
            elif method.upper() == 'DELETE':
                response = requests.delete(url, headers=headers, timeout=15)
            else:
                raise ValueError(f"Méthode HTTP non supportée : {method}")
            
            # Gérer les différents codes de statut
            if response.status_code == 200 or response.status_code == 201:
                # Succès
                return response.json() if response.text else {}
            
            elif response.status_code == 204:
                # Succès sans contenu (typique pour DELETE)
                return {}
            
            elif response.status_code == 400:
                # Erreur de validation
                errors = response.json().get('errors', [])
                print(f"Erreur 400 - Requête invalide :")
                for error in errors:
                    print(f"   - {error.get('message')}")
                raise EbayAPIError(400, errors)
            
            elif response.status_code == 401:
                # Token invalide ou expiré
                print("Erreur 401 - Authentification échouée")
                print("   Votre token est invalide ou a expiré. Obtenez-en un nouveau.")
                raise EbayAPIError(401, [{'message': 'Authentication failed'}])
            
            elif response.status_code == 403:
                # Permissions insuffisantes
                print("Erreur 403 - Accès interdit")
                print("   Vérifiez que votre application a les scopes nécessaires.")
                raise EbayAPIError(403, [{'message': 'Access forbidden'}])
            
            elif response.status_code == 404:
                # Ressource non trouvée
                print("Erreur 404 - Ressource non trouvée")
                raise EbayAPIError(404, [{'message': 'Resource not found'}])
            
            elif response.status_code == 429:
                # Rate limit dépassé
                print("Erreur 429 - Limite de taux dépassée")
                print("   Attendez avant de faire une nouvelle requête.")
                
                # Récupérer le header Retry-After si présent
                retry_after = response.headers.get('Retry-After')
                if retry_after:
                    print(f"   Réessayez après : {retry_after} secondes")
                
                raise EbayAPIError(429, [{'message': 'Rate limit exceeded'}])
            
            elif 500 <= response.status_code < 600:
                # Erreur serveur - retry possible
                print(f"⚠️  Erreur serveur {response.status_code} (tentative {attempt + 1}/{max_retries})")
                
                if attempt < max_retries - 1:
                    wait_time = 2 ** attempt  # Backoff exponentiel : 1s, 2s, 4s...
                    print(f"   Nouvelle tentative dans {wait_time} secondes...")
                    import time
                    time.sleep(wait_time)
                    continue  # Retenter
                else:
                    print("   Nombre maximum de tentatives atteint.")
                    raise EbayAPIError(response.status_code, [{'message': 'Server error'}])
            
            else:
                # Autre erreur
                print(f"❌ Erreur HTTP {response.status_code}")
                print(f"   Réponse : {response.text[:200]}")
                raise EbayAPIError(response.status_code, [{'message': response.text}])
                
        except requests.exceptions.Timeout:
            print(f"⏱️  Timeout (tentative {attempt + 1}/{max_retries})")
            if attempt < max_retries - 1:
                continue
            raise
        
        except requests.exceptions.RequestException as e:
            print(f"❌ Erreur réseau : {str(e)}")
            raise

def search_all_items_paginated(query, access_token, max_items=50, environment='sandbox'):
    """
    Recherche des produits avec pagination automatique.
    
    eBay Browse API utilise :
    - 'limit' : nombre de résultats par page (max 200)
    - 'offset' : position de départ (0, 200, 400...)
    
    Args:
        query (str): Terme de recherche
        access_token (str): Token OAuth
        max_items (int): Nombre maximum total d'items à récupérer
        environment (str): 'sandbox' ou 'production'
    
    Returns:
        list: Liste de tous les items récupérés
    """
    
    all_items = []
    offset = 0
    limit = 50  # Items par page (max 200 pour eBay)
    
    print(f"🔍 Recherche paginée : '{query}' (max {max_items} items)")
    
    while len(all_items) < max_items:
        # Ajuster le limit pour ne pas dépasser max_items
        current_limit = min(limit, max_items - len(all_items))
        
        print(f"\n📄 Page en cours : offset={offset}, limit={current_limit}")
        
        try:
            # Faire la requête pour cette page
            response = make_ebay_request(
                method='GET',
                endpoint='/buy/browse/v1/item_summary/search',
                access_token=access_token,
                params={
                    'q': query,
                    'limit': current_limit,
                    'offset': offset
                },
                environment=environment
            )
            
            # Extraire les items de cette page
            items = response.get('itemSummaries', [])
            total = response.get('total', 0)
            
            print(f"  {len(items)} items récupérés (total disponible : {total})")
            
            if not items:
                print("  Aucun item sur cette page, arrêt de la pagination")
                break
            
            # Ajouter à la liste globale
            all_items.extend(items)
            
            # Vérifier s'il y a plus de pages
            if len(all_items) >= total:
                print(" Tous les items disponibles ont été récupérés")
                break
            
            # Passer à la page suivante
            offset += current_limit
            
        except EbayAPIError as e:
            print(f" Erreur lors de la pagination : {e}")
            break
    
    print(f"\n Total récupéré : {len(all_items)} items")
    return all_items

import time
from datetime import datetime

class RateLimiter:
    """
    Gestionnaire de rate limiting simple.
    
    Suit les limites et attend automatiquement si nécessaire.
    """
    
    def __init__(self, calls_per_second=5):
        """
        Args:
            calls_per_second (int): Nombre maximum d'appels par seconde
        """
        self.calls_per_second = calls_per_second
        self.min_interval = 1.0 / calls_per_second  # Intervalle minimum entre appels
        self.last_call_time = 0
    
    def wait_if_needed(self):
        """Attend si nécessaire pour respecter le rate limit."""
        now = time.time()
        time_since_last_call = now - self.last_call_time
        
        if time_since_last_call < self.min_interval:
            wait_time = self.min_interval - time_since_last_call
            print(f"⏳ Rate limiting : attente de {wait_time:.2f}s...")
            time.sleep(wait_time)
        
        self.last_call_time = time.time()
    
    def check_response_headers(self, response):
        """
        Vérifie les headers de rate limiting de la réponse.
        
        Args:
            response (requests.Response): Réponse HTTP
        """
        limit = response.headers.get('X-RateLimit-Limit')
        remaining = response.headers.get('X-RateLimit-Remaining')
        reset = response.headers.get('X-RateLimit-Reset')
        
        if all([limit, remaining, reset]):
            print(f"📊 Rate Limit : {remaining}/{limit} appels restants")
            
            # Convertir le timestamp de reset
            reset_time = datetime.fromtimestamp(int(reset))
            print(f"   Réinitialisation : {reset_time.strftime('%Y-%m-%d %H:%M:%S')}")
            
            # Avertir si proche de la limite
            if int(remaining) < 100:
                print(" Attention : Proche de la limite !")

    """

        logger.error(json.dumps(log_entry))

# Module 1 : Fondamentaux des APIs

## 1.1 Qu'est-ce qu'une API ?

### Définition

Une **API** (Application Programming Interface) est un **contrat** qui définit comment des logiciels communiquent entre eux. 
C'est une interface qui expose des fonctionnalités d'un système à d'autres systèmes.

**Analogie** : Imaginez un restaurant. Le menu (API) liste les plats disponibles (endpoints). Le serveur (protocole HTTP) transmet votre commande (requête) à la cuisine (serveur) et vous rapporte le plat (réponse).

Définition technique

Une **API** est définie par un contrat qui précise :      
- Les endpoints disponibles (ex : /users, /orders/{id}, /buy/browse/v1/item_summary/search)     
- Les méthodes HTTP autorisées (ex : GET, POST, PUT, DELETE)     
- Le format d’échange des données (ex : JSON, XML, Protocol Buffers)     
- Les règles de sécurité (ex : OAuth2, API Key, Authorization: Bearer <token>)     
- Le schéma des requêtes et réponses (ex : { "email": "string", "password": "string" })     
- Les codes de retour (ex : 200, 201, 400, 401, 404, 500)     
- Le versioning (ex : /api/v1/users, /api/v2/users)         

On peut voir une API comme une couche d’abstraction qui expose des fonctionnalités d’un système via une interface stable et documentée.

#### Focus sur le contrat
Le **contrat d’API** — Définition globale

Le contrat d’API est la description formelle et stable de tout ce qu’un client doit savoir pour interagir correctement avec une API.      
Il définit ce qui est observable et garanti entre le client et le serveur.    

##### Ce que contient un contrat d’API

##### Endpoints

Les points d’entrée accessibles via une URL.

Exemple :
```{python}
GET /users  
POST /orders  
DELETE /users/{id}
```
Ils définissent **où appeler l’API**.

---

##### Méthodes HTTP

Les actions autorisées sur chaque endpoint :
```{python}
- GET → Lire
- POST → Créer
- PUT / PATCH → Modifier
- DELETE → Supprimer
- PATCH -> Modification partielle 
- HEAD -> Metadatas liées à la requête
```
Elles définissent **quelle opération est permise**.

---

##### Format d’échange

Le format des données envoyées et reçues :

- JSON
- XML
- Protocol Buffers

Il définit **comment les données sont structurées**.

---

##### Schéma des données

La structure précise des objets :

- Nom des champs
- Types (string, number, boolean…)
- Champs obligatoires ou optionnels
- Contraintes (format email, min/max…)

Il définit **quoi envoyer et quoi recevoir exactement**.

---

##### Paramètres

Les paramètres acceptés :

- Path parameters (`/users/{id}`)
- Query parameters (`?limit=10`)
- Body (JSON)

Ils définissent **comment personnaliser une requête**.

---

##### Authentification & Sécurité

Les règles pour accéder à l’API :

- Bearer Token
- API Key
- OAuth2

Elles définissent **comment prouver son identité**.

---

##### Codes de retour HTTP

Les statuts renvoyés selon le résultat :

- 200 → Succès
- 201 → Créé
- 400 → Requête invalide
- 401 → Non authentifié
- 404 → Ressource introuvable
- 500 → Erreur serveur

Ils définissent **comment interpréter la réponse**.

---

##### Structure des erreurs

Exemple :

```json
{
  "error": {
    "code": "INVALID_EMAIL",
    "message": "Email format is invalid"
  }
}
```
Elle définit comment **comprendre les échecs**.

---

##### Versioning

Permet de faire évoluer l’API sans casser les clients :

```{python}
/api/v1/users
/api/v2/users
```

Il garantit la stabilité dans le temps.

## 1.2 REST vs Autres Architectures

### Architecture REST (Representational State Transfer)

REST est un **style d'architecture** pour les systèmes distribués, basé sur 6 principes :

1. **Client-Serveur** : Séparation des préoccupations
2. **Sans état (Stateless)** : Chaque requête contient toutes les informations nécessaires
3. **Cacheable** : Les réponses doivent indiquer si elles peuvent être mises en cache
4. **Interface uniforme** : URLs standard, méthodes HTTP
5. **Système en couches** : Architecture modulaire
6. **Code à la demande** (optionnel) : Le serveur peut envoyer du code exécutable

---

Précisons ces points !      
**Stateless** (REST)      
Le serveur ne conserve aucun état de session entre deux requêtes.      
Chaque requête doit contenir :
- l’identification (ex: JWT)     
- le contexte nécessaire     
- toutes les données utiles     

**Stateful** (l’inverse)     
Le serveur stocke un état en mémoire ou en base.           
Exemple classique :     
- Login     
- Serveur crée une session     

---

**Cacheable** (REST)     
Dans REST, **cacheable** signifie que les réponses HTTP doivent indiquer clairement si elles peuvent être stockées temporairement afin de :     
- Réduire la charge serveur     
- Diminuer la latence    
- Économiser la bande passante    
- Améliorer la scalabilité    

On ne met pas en cache "une API", mais **la réponse HTTP complète** :     
- Status code    
- Headers    
- Body (ex: JSON)    

Quelles requêtes sont concernées ?     
Principalement : 
```html    
- `GET`    
- `HEAD`    
```

Pas concernées :     
```html
- `POST`    
- `PUT`    
- `PATCH`    
- `DELETE`     
``` 
(car elles modifient l’état)

**Deux mécanismes principaux**    
**Cache par durée**    
```http
Cache-Control: max-age=3600
```
→ La réponse est valide pendant 1 heure.
Le client ne recontacte pas le serveur durant ce délai.

**Cache conditionnel (ETag)**
```http
ETag: v1
```

Lors d’une nouvelle requête : If-None-Match: v1
Si la ressource n’a pas changé : 304 Not Modified     
→ Pas de renvoi du JSON.

ETag = **identifiant de version de la ressource.**

Où le cache est-il stocké ?    
Navigateur     
Proxy    
API Gateway    
CDN (Content Delivery Network) *Réseau de serveurs stockant des copies de ressources.*    

Directives importantes
```http
Cache-Control: public   # Cache possible par CDN
Cache-Control: private  # Cache navigateur uniquement
Cache-Control: no-store # Aucun stockage
````

Pourquoi c’est crucial ?    
Dans un système distribué :    
Le réseau est lent    
Les serveurs coûtent cher    
La latence est critique    
Un bon cache peut diviser la charge backend par 10 ou plus.    

---

**Interface uniforme**       
L’interface uniforme est le **principe REST** selon lequel toutes **les ressources sont manipulées de la même manière**, en utilisant des règles standardisées.      
Concrètement :      
Les ressources sont identifiées par des **URI** (/users/42)      
Les actions sont exprimées via les **méthodes HTTP** (GET, POST, PUT, DELETE, PATCH)      
Les échanges utilisent des **représentations standard** (souvent JSON)      
Les messages sont **auto-descriptifs** (headers HTTP explicites)      

---

**Layered System** (système en couches)    
Dans une API REST, une architecture en couches signifie que :    
Le système est composé de plusieurs niveaux intermédiaires, le client ne sait pas avec quelle couche il communique réellement.    
Chaque couche a une responsabilité spécifique.    

Concrètement, cela veut dire quoi ?    
Une requête peut traverser plusieurs composants :    
Client    
→ Cache    
→ Proxy    
→ API Gateway    
→ Service d’authentification    
→ Service métier    
→ Base de données    

Le client ne voit qu’un seul point d’entrée : **https://api.example.com**    
Il ignore totalement :    
s’il y a un cache    
s’il y a plusieurs microservices    

Cette séparation permet :    
**Scalabilité**      
On peut ajouter ou modifier une couche sans impacter le client.

**Sécurité**    
On peut insérer :    
un firewall    
une couche d’authentification    
un système de rate limiting    

**Maintenabilité**        
Chaque couche a une responsabilité unique :    
Auth    
Logging    
Cache    
Business logic    

L’inverse (non modulaire)    
Client → Serveur unique → Base      
Pas d’intermédiaire, tout est centralisé dans un seul composant.

### Comparaison avec d'autres architectures

| Architecture | Protocole | Format | Cas d'usage |
|--------------|-----------|--------|-------------|
| **REST** | HTTP/HTTPS | JSON, XML | APIs web modernes |
| **SOAP** | HTTP, SMTP | XML uniquement | Systèmes legacy, transactions complexes |
| **GraphQL** | HTTP | JSON | Requêtes flexibles, mobile |
| **gRPC** | HTTP/2 | Protocol Buffers | Microservices, performance critique |

**eBay utilise REST** pour ses APIs modernes (Buy, Sell, Commerce) et SOAP pour ses APIs traditionnelles (Trading, Shopping).

## 1.3 HTTP et ses Méthodes

### Le protocole HTTP

HTTP (HyperText Transfer Protocol) est le protocole de communication du web. Une transaction HTTP se compose de :

```
CLIENT                           SERVEUR
  │                                 │
  ├──── Requête HTTP ──────────────>│
  │     (Méthode, URL, Headers)     │
  │                                 │
  │<──── Réponse HTTP ──────────────┤
        (Status, Headers, Body)     │
```

### Les méthodes HTTP principales

| Méthode | Usage | Idempotent | Safe | eBay Example |
|---------|-------|------------|------|--------------|
| **GET** | Récupérer une ressource | ✅ | ✅ | Obtenir les détails d'un produit |
| **POST** | Créer une ressource | ❌ | ❌ | Créer un listing |
| **PUT** | Remplacer une ressource | ✅ | ❌ | Mettre à jour entièrement un listing |
| **PATCH** | Modifier partiellement | ❌ | ❌ | Modifier le prix d'un listing |
| **DELETE** | Supprimer une ressource | ✅ | ❌ | Supprimer un listing |

**Idempotent** : Une opération peut être répétée sans effets de bord supplémentaires.  
**Safe** : L'opération ne modifie pas l'état du serveur.

### Exemple concret avec l'API eBay Browse

```python
# GET : Rechercher des produits sur eBay
# Endpoint : /buy/browse/v1/item_summary/search
GET https://api.ebay.com/buy/browse/v1/item_summary/search?q=iphone&limit=5

# POST : Créer un listing (Sell API)
# Endpoint : /sell/inventory/v1/offer
POST https://api.ebay.com/sell/inventory/v1/offer
Body: { "sku": "ABC123", "marketplaceId": "EBAY_US", ... }

# PUT : Mettre à jour un listing complètement
PUT https://api.ebay.com/sell/inventory/v1/offer/12345
Body: { "sku": "ABC123", "quantity": 10, ... }

# DELETE : Retirer un listing
DELETE https://api.ebay.com/sell/inventory/v1/offer/12345
```

## 1.4 Structure des Requêtes et Réponses

### Anatomie d'une requête HTTP

```http
POST /sell/inventory/v1/offer HTTP/1.1
Host: api.ebay.com
Authorization: Bearer v^1.1#i^1#...
Content-Type: application/json
X-EBAY-C-MARKETPLACE-ID: EBAY_US

{
  "sku": "LAPTOP-001",
  "marketplaceId": "EBAY_US",
  "format": "FIXED_PRICE",
  "availableQuantity": 5,
  "pricingSummary": {
    "price": {
      "value": "999.99",
      "currency": "USD"
    }
  }
}
```

**Composants** :    
1. **Ligne de requête** : Méthode + URL + Version HTTP    
2. **Headers** : Métadonnées (autorisation, type de contenu)    
3. **Body** : Données (pour POST/PUT/PATCH)    

### Anatomie d'une réponse HTTP

```http
HTTP/1.1 201 Created
Content-Type: application/json
Date: Mon, 09 Feb 2026 10:30:00 GMT

{
  "offerId": "1234567890",
  "status": "PUBLISHED",
  "listingPolicies": {
    "fulfillmentPolicyId": "6789012345",
    "paymentPolicyId": "3456789012"
  }
}
```

**Composants** :    
1. **Ligne de statut** : Version HTTP + Code de statut + Message        
2. **Headers** : Métadonnées de réponse        
3. **Body** : Données retournées (généralement JSON)        

### Codes de statut HTTP

| Code | Signification | Exemple eBay |
|------|---------------|--------------|
| **2xx** | **Succès** | |
| 200 | OK | Requête réussie |
| 201 | Created | Listing créé |
| 204 | No Content | Suppression réussie |
| **3xx** | **Redirection** | |
| 301 | Moved Permanently | URL changée définitivement |
| **4xx** | **Erreur client** | |
| 400 | Bad Request | Données invalides |
| 401 | Unauthorized | Token manquant ou expiré |
| 403 | Forbidden | Accès refusé (permissions) |
| 404 | Not Found | Ressource inexistante |
| 429 | Too Many Requests | Limite de taux dépassée |
| **5xx** | **Erreur serveur** | |
| 500 | Internal Server Error | Erreur interne eBay |
| 503 | Service Unavailable | Maintenance |

## 1.5 Formats de Données : JSON vs XML

### JSON (JavaScript Object Notation)

Format **léger** et **lisible** par l'homme, standard pour les APIs REST modernes.

```json
{
  "itemId": "v1|110547012345|0",
  "title": "Apple iPhone 14 Pro Max - 256GB",
  "price": {
    "value": "1099.00",
    "currency": "USD"
  },
  "condition": "NEW",
  "seller": {
    "username": "apple_store",
    "feedbackScore": 98765
  },
  "itemLocation": {
    "city": "Cupertino",
    "country": "US"
  }
}
```

**Avantages** :    
- ✅ Léger et rapide à parser    
- ✅ Lisible par l'homme    
- ✅ Support natif en JavaScript    
- ✅ Utilisé par toutes les APIs eBay modernes (REST)    

### XML (eXtensible Markup Language)

Format **verbeux** mais **strictement typé**, utilisé par les APIs SOAP.

```xml
<?xml version="1.0" encoding="utf-8"?>
<GetItemResponse xmlns="urn:ebay:apis:eBLBaseComponents">
  <Timestamp>2026-02-09T10:30:00.000Z</Timestamp>
  <Ack>Success</Ack>
  <Item>
    <ItemID>110547012345</ItemID>
    <Title>Apple iPhone 14 Pro Max - 256GB</Title>
    <SellingStatus>
      <CurrentPrice currencyID="USD">1099.00</CurrentPrice>
    </SellingStatus>
    <Seller>
      <UserID>apple_store</UserID>
      <FeedbackScore>98765</FeedbackScore>
    </Seller>
  </Item>
</GetItemResponse>
```

**Avantages** :    
-  Validation stricte avec schémas (XSD)    
-  Support des namespaces    
-  Utilisé par les APIs eBay traditionnelles (Trading, Shopping)    

**Documentation eBay** : Les APIs REST eBay utilisent exclusivement JSON. Les APIs traditionnelles (SOAP) utilisent XML.

# Module 2 : Authentification et Sécurité

## 2.1 Pourquoi l'Authentification ?

L'authentification garantit :

1. **Identification** : Qui fait la requête ?
2. **Autorisation** : A-t-il le droit de le faire ?
3. **Traçabilité** : Audit et logs
4. **Limitation** : Rate limiting par utilisateur
5. **Facturation** : Suivi de la consommation

**eBay utilise OAuth 2.0** pour toutes ses APIs modernes.

## 2.2 Les Application Keysets eBay

Avant de faire des appels API, vous devez créer un **keyset** (jeu de clés) sur le portail développeur eBay.

### Composants d'un Keyset

| Composant | Description | Exemple | Confidentialité |
|-----------|-------------|---------|-----------------|
| **App ID (Client ID)** | Identifiant unique de votre app | `MyApp-MyComp-PRD-abc123456` | 🟢 Public |
| **Dev ID** | Identifiant développeur | `a1b2c3d4-e5f6-7890-abcd-ef1234567890` | 🟢 Public |
| **Cert ID (Client Secret)** | Mot de passe de l'app | `PRD-abc123456-789a-bcde...` | 🔴 SECRET |

**Documentation eBay** : Créez vos keysets sur [developer.ebay.com/my/keys](https://developer.ebay.com/my/keys).

**Important** : Créez des keysets **séparés** pour chaque environnement !

## 2.3 OAuth 2.0 : Le Standard d'Authentification

### Qu'est-ce qu'OAuth 2.0 ?

OAuth 2.0 est un **protocole d'autorisation** qui permet à une application d'accéder aux ressources d'un utilisateur **sans connaître son mot de passe**.

### Deux types de tokens OAuth eBay

#### 1. Application Access Token (App Token)

- **Usage** : Accès aux données publiques (recherche, browse)
- **Durée** : 2 heures
- **Pas de consentement utilisateur** requis

**Flux Client Credentials** :

```
┌─────────────┐                                ┌─────────────┐
│             │  1. POST /identity/v1/oauth2/  │             │
│   Votre App │────────────token──────────────>│  eBay Auth  │
│             │  (Client ID + Client Secret)   │   Server    │
│             │                                │             │
│             │<─────── 2. Access Token ───────┤             │
│             │    (expires_in: 7200)          │             │
└─────────────┘                                └─────────────┘
       │
       │ 3. Appels API avec token
       │
       ▼
┌─────────────┐
│  eBay API   │
│  (Browse,   │
│   Search)   │
└─────────────┘
```

#### 2. User Access Token (User Token)

- **Usage** : Accès aux données privées de l'utilisateur (listings, ordres)
- **Durée** : Varie selon les scopes
- **Consentement utilisateur** obligatoire

**Flux Authorization Code** :

```
┌──────────┐                                           ┌──────────┐
│          │  1. Redirection vers eBay login page      │          │
│  User    │──────────────────────────────────────────>│  eBay    │
│ (Browser)│                                           │  Login   │
│          │                                           │          │
│          │<─────── 2. Enter credentials ─────────────┤          │
└──────────┘                                           └──────────┘
     │                                                       │
     │ 3. Consent screen (scopes)                            │
     │<──────────────────────────────────────────────────────┤
     │                                                       │
     │ 4. Approve                                            │
     ├──────────────────────────────────────────────────────>│
     │                                                       │
     │ 5. Redirect to Your App with CODE                     │
     │<──────────────────────────────────────────────────────┤
     │                                                       │
     ▼                                                       │
┌──────────┐                                           ┌──────────┐
│  Your    │  6. Exchange CODE for Token               │  eBay    │
│  App     │──────────────────────────────────────────>│  Auth    │
│  Server  │  POST /identity/v1/oauth2/token           │  Server  │
│          │                                           │          │
│          │<─────── 7. Access + Refresh Tokens ───────┤          │
│          │                                           │          │
└──────────┘                                           └──────────┘
     │
     │ 8. API calls with Access Token
     │
     ▼
┌──────────┐
│  eBay    │
│  Sell    │
│  API     │
└──────────┘
```

### Scopes (Permissions)

Les **scopes** définissent les permissions demandées. Exemples eBay :

| Scope | Description | API |

| `https://api.ebay.com/oauth/api_scope/sell.marketing` | Marketing & promotions | Sell Marketing |
| `https://api.ebay.com/oauth/api_scope/commerce.catalog.readonly` | Lire le catalogue | Commerce |

**Documentation eBay** : Liste complète des scopes : [developer.ebay.com/api-docs/static/oauth-scopes.html](https://developer.ebay.com/api-docs/static/oauth-scopes.html)

```{python}
class EbayAPIError(Exception):
    """Exception personnalisée pour les erreurs eBay API."""
    
    def __init__(self, status_code, errors):
        self.status_code = status_code
        self.errors = errors
        
        # Construire le message d'erreur
        if errors:
            first_error = errors[0]
            message = f"eBay API Error {status_code}: {first_error.get('message', 'Unknown error')}"
        else:
            message = f"eBay API Error {status_code}"
        
        super().__init__(message)


def make_ebay_request(method, endpoint, access_token, 
                      marketplace='EBAY_US', environment='sandbox',
                      params=None, json_data=None, max_retries=3):
    """
    Fonction générique pour faire des appels à l'API eBay avec gestion d'erreurs.
    
    Args:
        method (str): Méthode HTTP (GET, POST, PUT, DELETE)
        endpoint (str): Endpoint API (ex: '/buy/browse/v1/item_summary/search')
        access_token (str): Token OAuth
        marketplace (str): Marketplace ID
        environment (str): 'sandbox' ou 'production'
        params (dict): Paramètres de requête (pour GET)
        json_data (dict): Corps de la requête (pour POST/PUT)
        max_retries (int): Nombre maximum de tentatives en cas d'erreur 5xx
    
    Returns:
        dict: Réponse JSON de l'API
    
    Raises:
        EbayAPIError: En cas d'erreur API
    """
    
    base_url = API_URLS[environment]['api']
    url = f"{base_url}{endpoint}"
    headers = build_ebay_headers(access_token, marketplace)
    
    for attempt in range(max_retries):
        try:
            # Faire la requête selon la méthode
            if method.upper() == 'GET':
                response = requests.get(url, headers=headers, params=params, timeout=15)
            elif method.upper() == 'POST':
                response = requests.post(url, headers=headers, json=json_data, timeout=15)
            elif method.upper() == 'PUT':
                response = requests.put(url, headers=headers, json=json_data, timeout=15)
            elif method.upper() == 'DELETE':
                response = requests.delete(url, headers=headers, timeout=15)
            else:
                raise ValueError(f"Méthode HTTP non supportée : {method}")
            
            # Gérer les différents codes de statut
            if response.status_code == 200 or response.status_code == 201:
                # Succès
                return response.json() if response.text else {}
            
            elif response.status_code == 204:
                # Succès sans contenu (typique pour DELETE)
                return {}
            
            elif response.status_code == 400:
                # Erreur de validation
                errors = response.json().get('errors', [])
                print(f"Erreur 400 - Requête invalide :")
                for error in errors:
                    print(f"   - {error.get('message')}")
                raise EbayAPIError(400, errors)
            
            elif response.status_code == 401:
                # Token invalide ou expiré
                print("Erreur 401 - Authentification échouée")
                print("   Votre token est invalide ou a expiré. Obtenez-en un nouveau.")
                raise EbayAPIError(401, [{'message': 'Authentication failed'}])
            
            elif response.status_code == 403:
                # Permissions insuffisantes
                print("Erreur 403 - Accès interdit")
                print("   Vérifiez que votre application a les scopes nécessaires.")
                raise EbayAPIError(403, [{'message': 'Access forbidden'}])
            
            elif response.status_code == 404:
                # Ressource non trouvée
                print("Erreur 404 - Ressource non trouvée")
                raise EbayAPIError(404, [{'message': 'Resource not found'}])
            
            elif response.status_code == 429:
                # Rate limit dépassé
                print("Erreur 429 - Limite de taux dépassée")
                print("   Attendez avant de faire une nouvelle requête.")
                
                # Récupérer le header Retry-After si présent
                retry_after = response.headers.get('Retry-After')
                if retry_after:
                    print(f"   Réessayez après : {retry_after} secondes")
                
                raise EbayAPIError(429, [{'message': 'Rate limit exceeded'}])
            
            elif 500 <= response.status_code < 600:
                # Erreur serveur - retry possible
                print(f"⚠️  Erreur serveur {response.status_code} (tentative {attempt + 1}/{max_retries})")
                
                if attempt < max_retries - 1:
                    wait_time = 2 ** attempt  # Backoff exponentiel : 1s, 2s, 4s...
                    print(f"   Nouvelle tentative dans {wait_time} secondes...")
                    import time
                    time.sleep(wait_time)
                    continue  # Retenter
                else:
                    print("   Nombre maximum de tentatives atteint.")
                    raise EbayAPIError(response.status_code, [{'message': 'Server error'}])
            
            else:
                # Autre erreur
                print(f"❌ Erreur HTTP {response.status_code}")
                print(f"   Réponse : {response.text[:200]}")
                raise EbayAPIError(response.status_code, [{'message': response.text}])
                
        except requests.exceptions.Timeout:
            print(f"⏱️  Timeout (tentative {attempt + 1}/{max_retries})")
            if attempt < max_retries - 1:
                continue
            raise
        
        except requests.exceptions.RequestException as e:
            print(f"❌ Erreur réseau : {str(e)}")
            raise
```

### Pourquoi la pagination ?

Les APIs limitent le nombre de résultats par requête pour :
-  Optimiser les performances
-  Réduire la charge réseau
-  Éviter les timeouts
-  Gérer de gros volumes de données

### Pagination dans l'API eBay Browse

```{python}
#| eval: false

def search_all_items_paginated(query, access_token, max_items=50, environment='sandbox'):
    """
    Recherche des produits avec pagination automatique.
    
    eBay Browse API utilise :
    - 'limit' : nombre de résultats par page (max 200)
    - 'offset' : position de départ (0, 200, 400...)
    
    Args:
        query (str): Terme de recherche
        access_token (str): Token OAuth
        max_items (int): Nombre maximum total d'items à récupérer
        environment (str): 'sandbox' ou 'production'
    
    Returns:
        list: Liste de tous les items récupérés
    """
    
    all_items = []
    offset = 0
    limit = 50  # Items par page (max 200 pour eBay)
    
    print(f"🔍 Recherche paginée : '{query}' (max {max_items} items)")
    
    while len(all_items) < max_items:
        # Ajuster le limit pour ne pas dépasser max_items
        current_limit = min(limit, max_items - len(all_items))
        
        print(f"\n📄 Page en cours : offset={offset}, limit={current_limit}")
        
        try:
            # Faire la requête pour cette page
            response = make_ebay_request(
                method='GET',
                endpoint='/buy/browse/v1/item_summary/search',
                access_token=access_token,
                params={
                    'q': query,
                    'limit': current_limit,
                    'offset': offset
                },
                environment=environment
            )
            
            # Extraire les items de cette page
            items = response.get('itemSummaries', [])
            total = response.get('total', 0)
            
            print(f"  {len(items)} items récupérés (total disponible : {total})")
            
            if not items:
                print("  Aucun item sur cette page, arrêt de la pagination")
                break
            
            # Ajouter à la liste globale
            all_items.extend(items)
            
            # Vérifier s'il y a plus de pages
            if len(all_items) >= total:
                print(" Tous les items disponibles ont été récupérés")
                break
            
            # Passer à la page suivante
            offset += current_limit
            
        except EbayAPIError as e:
            print(f" Erreur lors de la pagination : {e}")
            break
    
    print(f"\n Total récupéré : {len(all_items)} items")
    return all_items
```

## 3.4 Rate Limiting

### Qu'est-ce que le Rate Limiting ?

Le **rate limiting** limite le nombre de requêtes qu'une application peut faire sur une période donnée.

**Objectifs** :
- Protéger les serveurs contre les abus
-  Garantir une utilisation équitable
-  Monétiser l'usage (plans premium)

### Limites eBay API

| Type d'application | Appels/jour (défaut) | Appels/seconde |
|--------------------|----------------------|----------------|
| Sandbox | 5,000 | 5 |
| Production (de base) | 5,000 | 5 |
| Production (approuvé) | Sur demande | Variable |

**Documentation eBay** : Consultez [developer.ebay.com/support/api-call-limits](https://developer.ebay.com/support/api-call-limits) pour les limites détaillées.

### Headers de Rate Limiting eBay

```http
HTTP/1.1 200 OK
X-RateLimit-Limit: 5000
X-RateLimit-Remaining: 4950
X-RateLimit-Reset: 1707480000
```

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | Limite totale |
| `X-RateLimit-Remaining` | Appels restants |
| `X-RateLimit-Reset` | Timestamp de réinitialisation |

### Gestion du Rate Limiting

```{python}
#| eval: false

import time
from datetime import datetime

class RateLimiter:
    """
    Gestionnaire de rate limiting simple.
    
    Suit les limites et attend automatiquement si nécessaire.
    """
    
    def __init__(self, calls_per_second=5):
        """
        Args:
            calls_per_second (int): Nombre maximum d'appels par seconde
        """
        self.calls_per_second = calls_per_second
        self.min_interval = 1.0 / calls_per_second  # Intervalle minimum entre appels
        self.last_call_time = 0
    
    def wait_if_needed(self):
        """Attend si nécessaire pour respecter le rate limit."""
        now = time.time()
        time_since_last_call = now - self.last_call_time
        
        if time_since_last_call < self.min_interval:
            wait_time = self.min_interval - time_since_last_call
            print(f"⏳ Rate limiting : attente de {wait_time:.2f}s...")
            time.sleep(wait_time)
        
        self.last_call_time = time.time()
    
    def check_response_headers(self, response):
        """
        Vérifie les headers de rate limiting de la réponse.
        
        Args:
            response (requests.Response): Réponse HTTP
        """
        limit = response.headers.get('X-RateLimit-Limit')
        remaining = response.headers.get('X-RateLimit-Remaining')
        reset = response.headers.get('X-RateLimit-Reset')
        
        if all([limit, remaining, reset]):
            print(f"📊 Rate Limit : {remaining}/{limit} appels restants")
            
            # Convertir le timestamp de reset
            reset_time = datetime.fromtimestamp(int(reset))
            print(f"   Réinitialisation : {reset_time.strftime('%Y-%m-%d %H:%M:%S')}")
            
            # Avertir si proche de la limite
            if int(remaining) < 100:
                print(" Attention : Proche de la limite !")

# Exemple d'utilisation avec rate limiter
rate_limiter = RateLimiter(calls_per_second=2)  # 2 appels/seconde max

if 'app_token' in locals():
    searches = ['iphone', 'laptop', 'camera', 'headphones', 'watch']
    
    print(f" Recherche de {len(searches)} termes avec rate limiting...\n")
    
    for search_term in searches:
        # Attendre si nécessaire avant l'appel
        rate_limiter.wait_if_needed()
        
        try:
            response_raw = requests.get(
                f"{API_URLS[ENVIRONMENT]['api']}/buy/browse/v1/item_summary/search",
                headers=build_ebay_headers(app_token['access_token']),
                params={'q': search_term, 'limit': 1},
                timeout=10
            )
            
            # Vérifier les headers de rate limiting
            rate_limiter.check_response_headers(response_raw)
            
            if response_raw.status_code == 200:
                data = response_raw.json()
                total = data.get('total', 0)
                print(f"   '{search_term}' : {total} résultats\n")
            
        except Exception as e:
            print(f"   Erreur pour '{search_term}' : {e}\n")
```
